# Agent 发布页与运行恢复

Agent Studio 会根据开始节点的 JSON Schema 生成聚焦式单栏表单。发布前在 Studio 顶部点击“Agent 页面设置”，可配置页面标题（1–80 字符）、说明（最多 500 字符）、强调色、提交按钮文案（1–24 字符）和结果展示方式。设置与画布共用草稿修订号；发布后冻结到工作流版本，后续修改草稿不会改变既有版本或历史运行页面。

## 使用流程

1. 配置开始节点字段并完成工作流连线。
2. 打开“Agent 页面设置”，保存页面外观与结果模式。
3. 发布工作流，点击“打开 Agent 页面”。
4. 填写自动生成的表单并提交。服务端接受后，地址会变为 `?runId=<运行 ID>`。
5. 运行期间可以取消；断网后重连或刷新同一地址，会从持久化游标继续读取公开状态和增量事件。
6. 完成、失败或取消后点击“再次运行”，页面才会移除旧运行 ID、加载最新发布版本，并保留当前标签页内的表单值。

历史运行始终使用创建时冻结的标题、说明、强调色和结果模式。URL 中的运行 ID 只用于恢复；页面不会把输入、幂等键或运行数据写入 `localStorage` 或 `sessionStorage`，也不会展示节点 ID、中间输入输出或内部堆栈。

## 结果模式

- `auto`：字符串原样显示；其它 JSON 值按键排序并缩进。
- `text`：字符串原样显示；其它 JSON 值紧凑显示。
- `json`：所有值按键排序并缩进，字符串保留 JSON 引号。

结果仅作为文本输出，不解析 Markdown 或 HTML。循环引用、函数、非有限数字等非 JSON 值统一显示“结果无法安全序列化”。复制按钮复制屏幕上同一份安全格式化文本。

## 状态码与恢复

- `400/422`：输入或请求无效，修正表单后重试。
- `404`：Agent、版本或运行不存在，或运行不属于当前 Agent。
- `409`：工作流已归档等状态冲突。
- `429`：活动运行已达到容量上限，稍后重试。
- `503`：服务正在关闭或暂不可用，稍后重试。
- 网络错误与 `5xx`：页面按 1、2、4、8、10 秒退避重连，之后保持 10 秒间隔。

取消是协作式操作：请求成功后页面继续轮询，直到服务端把运行收敛为 `cancelled`。已发生的模型费用、Webhook 或其它外部副作用无法撤销。

## 运维配置与边界

活动异步 Agent 运行默认最多 8 个，可在 `.env` 调整：

```dotenv
MAX_ACTIVE_AGENT_RUNS=8
```

该限制作用于单个 API 进程，设置为正整数后需重启 API。运行由 API 进程内 supervisor 执行，不是独立队列或 Worker：浏览器刷新可以恢复已持久化状态，但 API 进程重启不会续跑正在执行的任务；关闭期间运行会安全收敛，客户端可能收到 `503`。

排查时先访问 `/healthz` 和 `/readyz`，确认 PostgreSQL 可用且 migration 最新；再核对 URL 中的 runId、浏览器网络状态以及 API 的公开错误码。不要从数据库、日志或内部运行管理接口向公开页面补充节点级详情。
