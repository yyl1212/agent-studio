# v0.5.0 GA 发布收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在画布 UX PR 合并后，准备并验证 `v0.5.0` 正式开发者预览版，最终从经过验证的 `main` 发布不可变 GA Release。

**Architecture:** PR2 只推进中文发布文档和静态文档契约。运行时仍使用 SDK `0.5.0`、Node API `v1alpha1`、migration 7 与既有 Release 工作流；合并后的 `main` 经完整回归、四平台 dry-run 和 preflight 后，annotated Tag 触发同一制品的原生冒烟与公开发布。

**Tech Stack:** Markdown、POSIX shell、Go 1.26、Node.js 24、pnpm 10.34.5、Docker PostgreSQL 18、GitHub Actions、GoReleaser。

**Spec:** `docs/superpowers/specs/2026-09-28-v0.5.0-ga-stabilization-design.md`

## Global Constraints

- PR1 合并、PR1 `main` CI 成功后，重新拉取最新 `origin/main`，创建 `codex/v0.5.0-ga-pr2-release` 分支与隔离工作树。
- GA Tag 为 `v0.5.0`；源码开发版 `0.5.0-dev`；SDK `0.5.0`；Node API `agent-studio.dev/v1alpha1`；官方 Runtime 范围 `[v0.2.0, v0.6.0)`；备份 v1alpha2 继续导入受支持的 v1alpha1；数据库 migration 7。
- 不主动修改 API、SDK、节点 manifest、Graph、数据库 migration、备份格式或运行引擎；任何非零兼容性差异先专项审核并修订方案。
- 文档使用中文，准确说明单租户、本地优先、无本地 RAG、无自动业务重试、无签名/公证；GA 表示正式开发者预览，不代表生产 SLA 或 v1 兼容承诺。
- 公开状态在 Tag 工作流成功前只用条件语气描述；不移动、删除、复用已推送的 Tag/Release。
- 每条测试命令由执行器限制在 600 秒内；构建单独按构建任务上限；所有 Go 调试与测试显式设置 `CGO_ENABLED=0`。

## Review Focus

1. README/升级手册仍把 `rc.1` 说成当前目标：新断言拒绝陈旧当前版本，Task 2 覆盖。
2. RC Notes 被 GA 文案覆盖或删减：历史 RC 全套断言继续执行，Task 1 覆盖。
3. GA Notes 在 Tag 前声称远端已公开：静态门禁拒绝无条件“已发布/已公开/Latest”，Task 1 覆盖。
4. 版本与兼容性漂移：SDK、API、manifest、migration、备份格式及官方节点相对 RC 不变，Task 3 审核。
5. 运行结果或附件不足时提前公开 GA：精确 `main` CI、四平台 smoke、9 附件和 Draft 复核门禁保持生效，Task 4、5 检查。

### Task 4：合并后主线 dry-run 与发布前检查

**Files:** 不修改仓库文件；只产生可核验的 CI、dry-run 与 preflight 证据。

**Interfaces:** Consumes 已合并 PR2 的精确 `main` 提交；produces 可供正式标签决策的发布证据。

- [ ] **Step 1: 核对合并提交。** `git fetch origin main --tags`，确认 PR2 为 MERGED、`origin/main` 等于合并提交，且该 SHA 对应的 `main` push CI 全部成功；保留 CI run URL。
- [ ] **Step 2: 从 main 手动触发无发布 dry-run。** `gh workflow run release.yml --ref main`；定位同一 SHA 且 `event=workflow_dispatch` 的 Release run，等待 Build 与 Linux/macOS amd64/arm64 四个 Smoke Job 成功，Publish Job 必须为 skipped。四个平台原生冒烟各自的测试步骤不能超过 10 分钟。
- [ ] **Step 3: 进入干净的主线检出执行 preflight。** 工作树 HEAD 与 `origin/main` 相等；确认本地、远端均无 `v0.5.0` Tag，GitHub 无同名 Release，运行 `CGO_ENABLED=0 make release-preflight TAG=v0.5.0` 并记录输出与精确 SHA。
- [ ] **Step 4: 报告证据。** 向用户提供 PR、main CI、dry-run、preflight 的链接与 SHA，以及下一步推送 annotated `v0.5.0` Tag 将自动公开正式 Release 的效果；在发布动作最终确认之前不推送 Tag。

### Task 5：正式标签、Release 与公开面冒烟

**Files:** 不修改仓库文件；对外创建唯一 GA Tag 与正式 Release。

**Interfaces:** Consumes Task 4 的已核实 `main` SHA、preflight 和最终发布确认；produces 不可变的 `v0.5.0` 正式 Release。

- [ ] **Step 1: 创建并复核 annotated Tag。** 在与 `origin/main` 相同的提交上执行 `git tag -a v0.5.0 -m 'Agent Studio v0.5.0' <main-sha>`；断言 `git cat-file -t v0.5.0` 为 `tag`、`git rev-list -n 1 v0.5.0` 为 `<main-sha>`、消息精确一致，再只推送 `refs/tags/v0.5.0`。
- [ ] **Step 2: 跟踪精确 Release run。** 只接受 `headBranch=v0.5.0` 且 `headSha=<main-sha>` 的 `push` 运行；Build、四个平台 Smoke 和 Publish Job 全部成功。失败时保留原 Tag/Release 状态，查明原因；不移动、覆盖标签或附件。
- [ ] **Step 3: 验证远端 Tag、Release 和附件。** 远端 ref 类型为 `tag` 且剥离后目标为 `<main-sha>`；`gh release view v0.5.0` 报 `isDraft=false`、`isPrerelease=false`、`isImmutable=true`，`gh release list` 显示它是 Latest；附件名称恰为四归档、四 SPDX 和 checksums，大小均大于 0。
- [ ] **Step 4: 验证公开可用性。** 从公开 Release 下载 9 件附件，运行 `sh scripts/check-release-artifacts.sh collection <download-dir> v0.5.0`；在当前宿主目标执行原生 archive 的 `agent-studio version`。用临时 `GOBIN` 与 `CGO_ENABLED=0` 从公开 Go Proxy 安装精确 `@v0.5.0`，验证 CLI、SDK `0.5.0`、API `v1alpha1`；记录 Release URL 与各项证据。
