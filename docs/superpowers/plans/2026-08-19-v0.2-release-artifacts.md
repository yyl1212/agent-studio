# Agent Studio v0.2 Developer Artifacts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 Agent Studio CLI 建立可重复的 macOS/Linux amd64/arm64 构建、SHA-256、SPDX SBOM、四平台冒烟和安全 Draft Release 流水线，作为 `v0.2.0-rc.2` 与 `v0.2.0` 的发布基础。

**Architecture:** GoReleaser OSS 在一个只读构建任务中交叉编译四个目标并生成唯一制品集合；该集合通过 GitHub workflow artifact 分发给四个原生 Runner 执行。只有标签运行且全部冒烟通过时，最终任务才创建 Draft、上传同一批附件、复核并公开；手动 dry-run 永远跳过发布。

**Tech Stack:** Go 1.26.5、POSIX shell、GoReleaser v2.17.1、Syft v1.51.0、Go `archive/tar`/`compress/gzip`/`crypto/sha256`、GitHub Actions、GitHub CLI、actionlint v1.7.12。

**Spec:** `docs/superpowers/specs/2026-08-19-v0.2-ga-stabilization-design.md`

## Global Constraints

- 本计划只实施规格 D1“开发者制品基础”，不得创建 `v0.2.0-rc.2` 标签或 GitHub Release。
- 不修改 SDK、节点协议、运行引擎、前端业务代码、数据库或官方节点。
- 支持目标固定为 `linux/amd64`、`linux/arm64`、`darwin/amd64`、`darwin/arm64`。
- 所有构建和 Go 调试使用 `CGO_ENABLED=0`。
- GoReleaser 固定 `v2.17.1`，Syft 固定 `v1.51.0`，actionlint 固定 `v1.7.12`。
- 归档格式固定 `tar.gz`；校验算法固定 SHA-256；SBOM 固定 SPDX JSON。
- macOS 二进制不签名、不公证，文档必须明确这一边界。
- 第三方 Action 使用完整 commit SHA，并在行尾注释可读版本。
- 测试先行、小提交；每个任务结束时保持工作树可验证。
- 推送分支、创建 PR、合并 `main` 和执行远程 dry-run 前分别取得用户确认。

- [ ] **Step 3: Implement collection verification**

在 `check.go` 定义：

```go
package releaseartifact

type Config struct {
	DistDir string
	Version string
	GOOS    string
	GOARCH  string
	Commit  string
}

type target struct {
	GOOS   string
	GOARCH string
}

var supportedTargets = []target{
	{GOOS: "linux", GOARCH: "amd64"},
	{GOOS: "linux", GOARCH: "arm64"},
	{GOOS: "darwin", GOARCH: "amd64"},
	{GOOS: "darwin", GOARCH: "arm64"},
}

func VerifyCollection(config Config) error
func VerifyTarget(config Config) error
```

`VerifyCollection` 必须按确定顺序执行：

1. 拒绝空 `DistDir` 或空 `Version`。
2. 为四个目标计算 `agent-studio_<version>_<goos>_<goarch>.tar.gz`。
3. 断言根目录恰好存在四个归档和四个 `<archive>.spdx.json`。
4. 解析 `checksums.txt` 的 `<64 hex><two spaces><filename>` 行。
5. 对每个归档流式计算 SHA-256 并使用 `subtle.ConstantTimeCompare` 比较。
6. 使用 `encoding/json.Decoder` 解析 SBOM，断言无尾随 JSON 且 `spdxVersion` 以 `SPDX-` 开头。
7. 聚合第一个稳定错误并用目标文件名提供上下文。

归档枚举只能使用 `os.ReadDir(config.DistDir)`，不得跟随未知路径或接受额外发布附件。

- [ ] **Step 4: Implement safe target extraction and execution**

`VerifyTarget` 先调用 `VerifyCollection`，再验证目标属于 `supportedTargets`。使用 `gzip.NewReader` 和 `tar.NewReader` 逐项读取归档，按以下规则处理：

```go
clean := path.Clean(header.Name)
if clean != header.Name || clean == "." || strings.HasPrefix(clean, "../") || path.IsAbs(clean) {
	return fmt.Errorf("unsafe archive path %q", header.Name)

```
