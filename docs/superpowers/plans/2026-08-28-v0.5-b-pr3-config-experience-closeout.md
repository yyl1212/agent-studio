# v0.5-B PR3 配置体验与收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将节点配置升级为聚焦式单栏、渐进披露且具有明确状态的编辑体验，并对会破坏连线的端口变化进行显式确认，完成响应式、可访问性、文档与全量回归收口。

**Architecture:** 保留通用 `SchemaForm`，用已有 JSON Schema UI 扩展表达必填、顺序、控件和提示；`useNodeConfigDraft` 继续拥有草稿、校验和端口解析状态；`configDraft` 产出结构化端口影响并保留失效边。`StudioPage` 统一编排普通应用、应用并试运行、脏草稿继续和破坏性确认，只有保存成功后才执行需要离开配置上下文的意图。

**Tech Stack:** React 19、TypeScript、AJV 2020、Vitest 4.1.10、Testing Library、Playwright、现有 SaveQueue 与 CSS Token。

**Spec:** `docs/superpowers/specs/2026-08-28-v0.5-b-canvas-ux-design.md`


对需要保存后动作的模式，flush 前写入 `pendingPostSaveAction`，成功执行后清除；非冲突保存失败时保留它和当前配置工作台，并设置明确 action error。`retrySaveAndContinue()` 重新 enqueue 当前完整图并等待 flush，成功后原子取出并执行该动作。409 冲突、用户放弃草稿、刷新工作流或切换到另一 workflow 时清除该状态，不得在新上下文误执行旧意图。

脏草稿确认框选择“应用并继续”时，先调用 `workbench.resolveDirty('apply')` 取出并清除原 pending intent，再构造 `apply-and-continue`；这样取消第二层端口确认后不会重新弹出第一层确认。确认破坏性变化后：普通 apply 继续；apply-and-test 只应用并显示“配置已应用，请先修复失效连线后试运行”，且不写入 `pendingPostSaveAction`；apply-and-continue 的目标为 test/publish 时不离开，其他编辑意图在保存成功后继续。
