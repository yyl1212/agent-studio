# Agent Studio v0.3.0-rc.3 与 GA 收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以只含发布文档的 PR 冻结当前 `main`，发布经过完整制品与 immutable 验证的 `v0.3.0-rc.3`，并在单独用户确认后发布同一受测提交的 `v0.3.0` GA。

**Architecture:** 复用现有 annotated Tag → Release workflow → 四平台制品/SBOM → Draft 远端比对 → immutable 公开链路，不修改产品或发布代码。文档 PR、rc.3 Tag 和 GA Tag 是三个独立外部状态门禁；rc.3 不设置时间观察窗口，但所有技术验证必须完成，任何漂移或阻塞都停止 GA 并转入修复 PR 与递增 RC。

**Tech Stack:** Git/GitHub CLI、GitHub Actions、Bash、Go 1.26.5（`CGO_ENABLED=0`）、GoReleaser 2.17.1、Syft 1.51.0、Docker PostgreSQL 18、pnpm 10.34.5、Playwright 1.62。

**Spec:** `docs/superpowers/specs/2026-08-22-v0.3.0-rc.3-release-design.md`

## Global Constraints

- rc.3 内容冻结为执行时最新 `origin/main` 已包含的 v0.3-A/B/C/D；只有门禁发现的阻塞修复可以改变产品代码，且必须停止本计划、另开修复 PR。
- 计划内仓库差异只允许：新增 rc.3 Notes、更新 GA Notes、设计规格和本计划；README、产品代码、测试实现、依赖锁、SDK、OpenAPI、migration、Release workflow、GoReleaser 配置和发布脚本均不得修改。
- `v0.3.0-rc.3` 与 `v0.3.0` 必须是 annotated Tag、指向各自创建时最新且相同的 `origin/main`；禁止 lightweight Tag、force push、移动、覆盖或复用标签。
- 发布文档 PR 合并、rc.3 Tag 推送和 GA Tag 推送分别取得用户明确确认；前一步确认不预授权后一步。
- rc.3 取消固定时间观察，但不得跳过本地完整门禁、PR CI、四平台 smoke、九附件、checksum、SBOM、源码安装、原生制品和 `immutable=true` 验证。
- 所有 Go 命令使用 `CGO_ENABLED=0`。
- 任何命令非零退出、远端状态未知、附件不完整、`immutable!=true`、main 漂移或 Critical/Important 都立即停止；不得降级为 warning。
- 已公开的失败 RC/GA 外部状态保留用于审计；阻塞修复使用新 PR 和递增 `v0.3.0-rc.4`，不模糊清理。
- 不创建节点索引投稿、容器镜像、Windows 制品、签名、公证或本地 RAG 相关内容。
