# v0.5-D 持久化运行与跨重启恢复实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将当前由 API 请求进程内执行的工作流，升级为 PostgreSQL 持久化排队、独立 Worker 租约执行、跨进程重启恢复，并为不确定节点提供受控人工恢复。

**Architecture:** API 仅负责校验、原子创建 `queued` 运行和跟随公开事件；Worker 通过 PostgreSQL `FOR UPDATE SKIP LOCKED` 领取运行，使用租约 token 对所有写入 fencing，并从事件日志与加密私有载荷重建检查点。公开审计数据继续脱敏，真正执行所需输入/输出写入 `run_payloads` 并使用 AES-256-GCM 加密。

**Tech Stack:** Go 1.26、PostgreSQL 18、pgx/v5、Chi、React 19、TypeScript 5.9、Vite 8、Vitest 4、Playwright 1.62、Docker Compose、OpenTelemetry。

**Spec:** `docs/superpowers/specs/2026-09-01-v0.5-d-durable-runs-design.md`

## Global Constraints

- 开发开始前必须切回 `main`、拉取远端最新代码，并从该提交创建 `codex/v0.5-d-durable-runs`；不得在设计分支直接开发。
- 所有 Go 调试、测试、生成和构建命令显式设置 `CGO_ENABLED=0`。
- API 与 Worker 必须使用同一镜像、同一代码版本和同一 `RUN_PAYLOAD_ENCRYPTION_KEY`；不支持新旧执行协议混跑。
- `RUN_PAYLOAD_ENCRYPTION_KEY` 为强制配置：标准 Base64 编码的 32 字节密钥。缺失、格式错误或长度错误时 API、Worker 都必须启动失败。
- v0.5-D 不实现密钥轮换；恢复备份必须使用创建备份时的相同密钥，密钥不进入备份、日志或 API 响应。
- 所有私有执行载荷非空值都必须密文落库；公开 `runs`、`run_events`、`node_runs` 继续只保存脱敏值。
- 运行协议版本固定为 `1`；未知协议不能领取，进入人工恢复或显式报错，不能猜测执行。
- Worker 默认并发为 `1`，但协议必须通过租约 token 支持多 Worker；任何事件、载荷、节点投影和终态写入都必须校验 fencing token。
- 节点最大尝试次数固定为 `3`。`pure` 不确定节点可自动重跑；`read_only`、`side_effect` 不确定节点只允许人工确认重跑或终止。
- 不提供跳过节点、手工标记成功或修改历史载荷的恢复动作。
- HTTP 客户端断开只能停止事件跟随，不能取消运行；取消只能通过显式取消 API。
- 备份格式升级为 `v1alpha2` 并包含 `run_payloads`；同时保留 `v1alpha1` 导入兼容。
- 每个任务严格遵循红—绿—重构：先写失败测试、确认失败原因、最小实现、运行通过，再提交。
- 不修改与本阶段无关的工作树文件；每个审查门结束都要执行代码审查和对应回归。

## 交付结构与审查门

```text
浏览器 / API 客户端
        │ 创建运行 / 跟随事件 / 人工恢复
        ▼
┌──────────────────────── API 进程 ────────────────────────┐
│ 校验与排队 │ NDJSON EventFollower │ Recovery API │ 查询   │
└──────────────────────────┬────────────────────────────────┘
                           │ PostgreSQL 事务
                           ▼
┌──────────────────────── PostgreSQL ───────────────────────┐
│ runs + lease token │ run_events │ node_runs │ run_payloads│
└──────────────────────────┬────────────────────────────────┘
                           │ SKIP LOCKED + lease/fencing
                           ▼
┌──────────────────────── Worker 进程 ──────────────────────┐
│ Claim │ Rehydrate │ Engine checkpoint │ Persist │ Renew    │
└───────────────────────────────────────────────────────────┘
```

|---|---:|---|
| A：持久化基础 | 1–5 | 状态/协议、迁移、加密载荷、租约存储、备份 v1alpha2 |

| C：API 与恢复 | 11–16 | 排队提交、事件跟随、取消、恢复 API、调试兼容、OpenAPI |
| D：页面与发布 | 17–21 | 管理端恢复体验、Agent 状态、Compose、故障注入、文档与发布门禁 |

- 已修复 P1：持久化局部重跑在 Worker 重建时丢失 execution scope/frozen edges；新增 scoped checkpoint 执行与单元/浏览器回归。
- 已修复 P1：完整历史校验拒绝从未启动即取消的下游节点，导致失败运行事件端点返回 409；校验规则已与引擎事件语义对齐。
