# Agent Studio v0.3-C 索引集成与发布 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 对 C1–C3 做跨仓稳定化，发布 Agent Studio v0.3.0，再把其官方节点包固定收录进不可变索引并完成真实刷新烟测。

**Architecture:** Agent Studio Release 和索引 Release 保持两个版本域：先冻结、验证并发布 Agent Studio v0.3.0，再用其不可变 Tag/commit/manifest digest 更新官方索引，发布索引 v0.2.0。已发布 v0.3.0 客户端保留逐字节固定的官方 v0.1.0 空快照，通过用户显式 refresh 获取首个真实包。

**Tech Stack:** Go 1.26.5、React/TypeScript、PostgreSQL 18、Playwright、GoReleaser 2.17.1、Syft 1.51.0、GitHub Actions/CLI、GitHub immutable releases。

**Spec:** `docs/superpowers/specs/2026-08-20-v0.3-git-node-index-design.md`

## Global Constraints

- 本计划只能在 C1 `v0.1.0`、C2、C3 均完成并合并后开始。
- 开始前拉取最新 `origin/main`，在 `/Users/wiw/Documents/ChatGPT/agent_improve/.worktrees/v0.3-c-index-stabilization` 创建 `codex/v0.3-c-index-stabilization` 隔离 worktree。
- Go 常规验证统一设置 `CGO_ENABLED=0`；race detector 与该约束冲突，不作为门禁，使用确定性交错和压力测试替代。
- v0.3.0 保持 Node API `agent-studio.dev/v1alpha1`，Go Node SDK 升为 `0.3.0`。
- v0.3.0 不增加数据库迁移，不自动安装节点，不让 API/Web 刷新索引。
- 所有 RC/GA Tag 都必须是 annotated Tag、指向最新 `origin/main`、公开后不可移动或复用。
- RC 和 GA 发布、PR 合并、索引投稿合并、索引 Release 都是外部状态变更；每次执行前取得用户明确授权。
- RC 只用于稳定化，不进入默认 stable 包推荐；索引首次收录只指向 Agent Studio GA `v0.3.0`。
- 索引发布版本从 `v0.1.0` 单调升级到 `v0.2.0`；不得覆盖旧 Release。
- 所有文档中文，公开说明不得把“已审核元数据”表述为代码安全认证。
- 完成前执行全量代码审查、Go/Web/OpenAPI/E2E、PostgreSQL、Release 制品和真实 GitHub smoke。
