# Agent Studio 节点库添加体验优化设计

**状态：** 已批准，等待规格审阅

**日期：** 2026-08-27

**基线：** `origin/main` @ `2eb6d7b`（v0.4.0 全画布 Studio）

**设计分支：** `codex/node-library-ux`

## 1. 背景

Agent Studio 已具备全画布工作台、节点库搜索、键盘选择、视口中心放置、防重叠定位、自动保存和添加后自动配置。当前节点库仍是按分类纵向堆叠的简单列表；当节点规模增长到 20–50 个时，分类浏览、常用节点复用和精确放置效率不足，卡片的信息层级也较弱。

本阶段聚焦“找到节点并顺滑地添加到画布”，不同时改造节点配置表单、画布节点视觉、节点定义契约或本地 RAG。用户已经选定“分层侧边节点库”：点击是主要添加方式，拖拽是桌面端的精确放置补充；添加成功后立即关闭节点库并打开新节点配置。

## 2. 目标与验收主线

核心操作链路为：

```text
打开节点库 → 搜索或按分类浏览 → 点击或拖拽节点 → 创建并保存 → 立即配置
```

目标：

- 20–50 个节点下仍能快速浏览和搜索；
- 最近使用节点在刷新后可恢复，但存储异常不能阻塞添加；
- 点击节点时放置在当前视口中心附近并避开已有节点；
- 桌面端可把节点拖拽到指定画布位置；
- 点击与拖拽复用同一创建、保存、最近使用和打开配置流程；
- 键盘、触摸设备和存储不可用场景都有完整降级路径；
- 不修改 Go 后端、PostgreSQL、OpenAPI、节点 SDK 或工作流 JSON。

## 3. 范围

### 3.1 本阶段交付

- 将现有节点库调整为“分类栏 + 搜索 + 最近使用 + 紧凑卡片”的分层侧边面板；
- 使用现有 `category`、标题、描述、类型和包元数据完成本地筛选与展示；
- 在浏览器本地维护最近使用的 6 个 `type@version`；
- 保持点击添加主流程，并继续使用视口中心和防重叠定位；
- 增加桌面端从节点卡片拖拽到画布指定位置；
- 添加移动端全宽单列和无拖拽降级；
- 补齐纯逻辑、组件、页面集成和 Playwright 回归测试。

### 3.2 明确不做

- 不增加收藏、推荐权重、标签、图标配置或服务端最近使用；
- 不跨浏览器、账号或设备同步使用记录；
- 不修改节点定义和节点包清单契约；
- 不引入新的全局状态库、拖拽框架或通知系统；
- 不调整节点配置表单和画布节点视觉；
- 不开发本地 RAG 闭环。

## 4. 方案选择

### 4.1 选定方案：前端增强、契约不变

所有目录信息从现有 `NodeDefinition` 派生，最近使用存放在 `localStorage`，节点放置继续由 React Flow 画布能力和 `StudioPage` 领域编排完成。该方案能直接改善节点规模增长后的操作效率，同时把兼容范围限制在 Web Studio。

### 4.2 未采用方案

- **扩展节点元数据契约：** 可增加图标、搜索关键字和推荐位，但会波及 OpenAPI、Go 类型、SDK、节点包清单和兼容性治理，当前收益不足。
- **只调整 CSS：** 风险最低，但无法解决分类导航、最近使用和精确拖放，不能达到主要体验目标。

## 5. 总体架构

```mermaid
flowchart TB
    API[现有节点定义 API] --> Model[nodeLibraryModel\n筛选 / 分类 / 最近使用]
    Storage[(localStorage\ntype@version × 6)] <--> Model
    Model --> Drawer[NodeLibraryDrawer\n分类栏 / 搜索 / 节点卡片]

    Drawer -->|点击定义| Page[StudioPage\n统一 createNode]
    Drawer -->|拖拽 type@version| Canvas[WorkflowCanvas\n坐标转换 / 放置事件]
    Canvas -->|定义键 + 画布坐标| Page

    Page --> Placement[nodePlacement\n网格吸附 / 防重叠]
    Placement --> Graph[受控 nodes / edges]
    Graph --> Queue[SaveQueue]
    Page --> Workbench[配置工作台]
    Page --> Model
```

边界约束：

- `nodeLibraryModel` 只处理目录数据派生和受保护的最近记录读写，不渲染界面；
- `NodeLibraryDrawer` 负责浏览、搜索、键盘操作和拖拽入口，不创建工作流节点；
- `WorkflowCanvas` 只把屏幕坐标转换为画布坐标，并向上报告放置意图；
- `StudioPage` 是创建节点、写入图状态、进入保存队列和切换工作台的唯一编排者；
- `nodePlacement` 负责可独立测试的网格吸附和防重叠算法；
- `SaveQueue` 仍是工作流持久化的唯一入口。

## 6. 信息架构与视觉布局

### 6.1 桌面端

节点库沿用左侧浮动面板，不改变 React Flow 容器尺寸。内容分为两栏：

- 左侧窄分类栏：`全部`、`最近`、以及从现有定义派生的分类；
- 右侧目录区：固定在顶部的搜索框、最近使用区、当前分类标题和两列紧凑卡片。

节点卡片展示标题、最多两行描述、包显示名和可用版本。整张卡片可点击；可拖拽提示作为辅助视觉出现，但不占用单独主按钮。分类按钮显示选中态，搜索结果显示数量。

### 6.2 搜索和分类关系

- 没有搜索词时，目录按当前分类展示；“全部”顶部优先展示最近使用，然后展示分类分组；
- “最近”只展示仍存在于当前定义列表的最近记录；
- 输入搜索词后临时跨分类搜索全部节点，不受当前分类限制；
- 清除搜索后恢复用户进入搜索前的分类；
- 搜索字段包括标题、描述、类型、包名和包显示名，采用大小写不敏感的包含匹配；
- 开始节点和结束节点继续从可添加目录中排除。

### 6.3 响应式

- `>= 640px`：分层侧边面板和两列卡片，支持点击与原生拖放；
- `< 640px`：面板占满可用宽度，分类栏改为横向滚动，卡片为单列；
- 触摸和窄屏设备不依赖原生拖放，完整保留点击添加；
- 禁止新增页面级横向滚动，遵守现有语义 Token 和 `prefers-reduced-motion`。

## 7. 组件与数据设计

### 7.1 `nodeLibraryModel`

提供以下稳定职责：

- 用 `nodeKey = type + "@" + version` 唯一标识目录项；
- 过滤不可添加定义并进行搜索；
- 按首次出现顺序派生分类和分类内节点；
- 从最近键解析当前仍有效的定义；
- 对最近记录去重、前置、裁剪至 6 个并清理失效值；
- 保护所有 `localStorage` 访问，解析失败或写入失败时返回空最近列表而不是抛错。

存储键使用带版本的命名空间，例如 `agent-studio.node-library.recent.v1`。存储值只包含字符串数组，不持久化完整节点定义。

### 7.2 `NodeLibraryDrawer`

组件继续接收当前 `definitions`、`onAdd` 和 `onClose`，并在卡片开始拖拽时写入节点键载荷。它拥有查询词、当前分类和键盘活动项，但不拥有图状态。

打开时聚焦搜索框；方向键在当前视觉顺序中循环移动，`Enter` 走点击添加，`Escape` 关闭面板。分类按钮使用 `aria-pressed`，搜索结果计数、空状态和错误提示使用 `aria-live`。关闭后由现有 Studio 壳层把焦点还给“添加节点”触发按钮。

### 7.3 `WorkflowCanvas`

在现有 `WorkflowCanvasHandle.getViewportCenter()` 基础上增加受限的屏幕坐标转画布坐标能力。画布接受拖放时只读取自定义 MIME 载荷中的 `type@version`，并向 `StudioPage` 报告定义键和画布坐标。

`dragover` 只在载荷类型匹配且工作流可编辑时进入可放置状态；定义是否仍有效由拥有当前定义列表的 `StudioPage` 在释放时判断。离开画布、按 `Escape` 或无效释放都不改变图状态。

### 7.4 `StudioPage` 与 `nodePlacement`

`StudioPage` 把现有 `addNode` 收敛为接收定义和可选位置的统一创建函数：

- 点击添加使用 `getViewportCenter()`，再执行防重叠定位；
- 拖拽添加使用释放点的画布坐标并吸附到 20px 网格；目标未被完全占用时不再偏移，目标会完全覆盖已有节点时才按确定性顺序寻找最近空位；
- 两条路径只创建一个节点、只进入一次 `SaveQueue`、只更新一次最近使用；
- 创建完成后关闭节点库、选中新节点并打开配置工作台；
- 归档工作流继续禁止所有添加行为。

现有 `availableNodePosition` 从 `StudioPage.tsx` 提取到 `nodePlacement.ts`，保持点击放置的行为兼容，并为拖拽位置增加 20px 网格吸附。空闲释放点四舍五入到最近网格，单轴误差最多 10px；只有释放点会完全覆盖已有节点时才允许超出该误差并寻找最近空位。算法必须是确定性的，测试不依赖 DOM 尺寸。

## 8. 核心交互与数据流

### 8.1 点击添加

```text
点击节点卡片
  → 读取当前视口中心
  → 计算最近可用位置
  → 创建默认配置和端口
  → 更新受控节点数组并 enqueue 保存
  → 最近记录去重前置
  → 关闭节点库
  → 打开新节点配置
```

视口中心被占用时，按固定网格逐步寻找最近空位。画布实例尚未就绪时使用现有 `{ x: 320, y: 260 }` 回退中心，再执行同一防重叠算法。

### 8.2 拖拽添加

1. 卡片开始拖拽时只写入自定义 MIME 类型和 `type@version`；
2. 画布命中有效载荷后显示可放置状态；
3. 释放时将 `clientX/clientY` 转为 React Flow 坐标；
4. `StudioPage` 用当前定义列表重新解析键，防止使用陈旧对象；
5. 网格吸附并处理重叠后调用统一创建函数；
6. 成功后关闭节点库并打开配置。

拖出画布、取消拖拽或定义解析失败时不创建节点、不保存、不更新最近使用。

### 8.3 脏配置保护

打开节点库继续走现有工作台意图：当前配置有未应用修改时，先展示“应用 / 放弃 / 取消”确认框。只有处理完成后才能关闭旧配置并打开节点库，因此添加新节点时不存在两份配置草稿竞争或旧草稿静默丢失。

## 9. 异常、降级与可访问性

| 场景 | 处理方式 |
|---|---|
| 最近存储不可用或损坏 | 返回空最近列表；搜索、分类和添加继续可用 |
| 最近记录引用失效定义 | 忽略并在下次成功写入时清理 |
| 搜索无结果 | 展示空状态、结果数量和“清除搜索” |
| 拖拽定义键失效 | 不创建节点；节点库保持打开并提示重新选择 |
| 画布坐标转换未就绪 | 使用确定性回退中心；点击流程继续可用 |
| 保存失败或冲突 | 沿用顶部保存状态；节点保留在本地编辑状态，不显示虚假成功提示 |
| 归档工作流 | 不开放节点库或拖放入口，不改变图状态 |

可访问性约束：

- 节点卡片保持标准按钮，拖放永远不是唯一操作方式；
- 打开后聚焦搜索框，关闭后恢复触发按钮焦点；
- 分类使用按钮和 `aria-pressed`，不使用仅靠颜色表达的状态；
- 方向键、`Enter`、`Escape` 完成浏览、添加和退出；
- 搜索计数、空状态和拖放错误通过 `aria-live` 播报；
- 拖放视觉状态遵守 reduced-motion，不能以动画作为唯一反馈。

### 11.2 自动化验证

### 11.3 关键测试场景

- 20–50 个定义下按分类浏览和跨分类搜索；

## 12. 验收标准

- 使用 50 个定义的测试夹具时，搜索和分类过滤不发起网络请求，并在当前交互内同步更新结果；
- 点击节点只创建一个实例，位置接近当前视口中心并避免完全重叠；
- 空闲目标上的拖拽位置与释放点单轴偏差不超过 10px；目标完全被占用时必须落到最近的非重叠网格位置；
- 添加后立即进入新节点配置；
- 最近使用在页面刷新后保留，浏览器存储失败不阻塞添加；
- 移动端不依赖拖拽，点击流程完整可用；
- 全键盘可以完成搜索、选择和添加；
- 前端测试、类型检查、构建、E2E 和仓库全量回归通过。

## 13. 可行性与阻塞项审查

设计不存在阻塞性问题：

- 当前 `NodeDefinition` 已包含分类、标题、描述、类型、版本和包元数据，足以完成目录展示与搜索；
- 当前 `WorkflowCanvasHandle` 已提供 React Flow 实例支撑的视口中心接口，可增量增加屏幕坐标转换而无需重写画布；
- 当前 `StudioPage.addNode` 已实现视口中心、防重叠、默认配置、单次保存和添加后打开配置，可收敛为带可选位置的统一入口；
- 当前节点库已具备搜索自动聚焦、方向键、回车和 Escape，可在现有组件上渐进扩展；
- `localStorage` 和原生 HTML 拖放不需要新增运行时依赖，移动端有点击流程兜底；
- 所有后端、数据库、OpenAPI 和 SDK 接口保持不变。

需要在实施计划中控制的风险：

1. 原生拖放在 jsdom 中不能完整代表浏览器行为，因此组件测试只验证载荷和回调，实际坐标链路由 Playwright 覆盖；
2. 点击与拖拽必须共用创建函数，防止保存次数、最近记录或配置切换出现分叉；
3. 分类和搜索改变视觉顺序后，键盘活动项必须重新对齐，避免焦点指向已隐藏元素；
4. 最近记录属于增强能力，任何读写异常都必须被隔离，不能影响核心添加流程；
5. `StudioPage.tsx` 已承担较多编排职责，位置算法应提取为纯模块，但不进行无关状态重构。

上述风险均可通过现有接口、TDD 分层测试和真实浏览器回归控制，不需要扩大范围或引入新依赖。
