# 运行管理与恢复

Agent Studio 的“运行”页面提供跨工作流的运行摘要、详情、协作取消、完整重试和人工恢复。API 负责接收请求与查询，独立 Worker 通过 PostgreSQL 租约领取并执行运行。

## 查找与刷新

可按工作流 ID、运行 ID、状态、模式和最多 90 天的开始时间范围筛选。筛选条件保存在 URL 中，便于刷新和分享。当前第一页包含“排队中”“运行中”“等待人工恢复”或“取消中”记录时，页面智能刷新；页面隐藏或查看后续页时暂停，不会用后台第一页打断当前焦点。

## 取消

排队运行可直接取消；执行中运行按 `运行中 → 取消中 → 已取消` 收敛；等待人工恢复的运行可直接终止为已取消。Worker 通过租约心跳观察取消请求并停止尚未完成的工作。取消不能撤销已经产生的模型费用、Webhook 或其他外部副作用。

API 或浏览器退出不影响已排队或执行中的运行。Worker 异常退出后，已完成节点保持冻结；租约到期后，新 Worker 会接管纯节点，遇到无法证明是否已完成的只读或副作用节点则进入人工恢复，不会静默重放。

## 人工恢复

状态为“等待人工恢复”时，在运行详情打开“恢复处理”。页面列出不确定节点、安全等级、尝试次数和稳定原因，但不显示密文、租约 owner 或私有输入输出。

- “确认重试”只对服务端判定允许重试的节点开放。逐个确认后，运行重新排队并从持久化检查点继续。
- `read_only` 重试可能再次产生模型费用或读取到变化后的外部数据。
- `side_effect` 重试可能重复发送 Webhook、写入外部系统或产生费用；必须先在外部系统核对第一次尝试是否生效，再确认。
- “终止运行”把运行收敛为已取消，不会撤销已发生的副作用。载荷缺失、错误密钥、历史损坏或节点不可用等不可重试场景只能终止后重新提交。

恢复命令使用页面当前的事件序号做乐观并发检查。若其他管理员已处理，页面会提示冲突并刷新，而不是重复确认。人工恢复只存在于管理端；公开 Agent 页面仅提示等待管理员处理。

## 完整重试

只有失败或已取消的草稿测试、已发布运行可以完整重试。已完成、仍在运行、取消中、局部调试以及已归档工作流不可重试。

重试固定使用原运行的图快照或原发布版本，不读取后来变化的当前草稿。普通输入只读展示；历史中被脱敏为 `[REDACTED]` 的秘密必须重新填写。秘密只保存在当前组件内存和执行期内存中，不进入 URL、浏览器存储、公共 Run JSON、事件、输出或日志。

每次对话框会生成一个 UUID 幂等键。网络中断后再次提交复用同一键，数据库只创建一个新 Run；若服务端已经创建，页面会切换到既有 Run。成功或关闭后会清空组件内的秘密与幂等键。

## 与局部重跑的区别

- 完整重试从开始节点执行整个历史工作流，模式保持为草稿测试或已发布运行。
- 调试局部重跑从选定节点开始，复用可证明安全的历史冻结边，并生成 `debug` 运行。
- 两者都不会自动重试业务失败节点；完整重试从头创建新运行，人工恢复则在 Worker 故障后沿原运行检查点继续。包含外部副作用时都应先确认影响。

## 安全边界

详情只展示公开错误和脱敏后的输入、输出与节点记录。`Idempotency-Key` 只作为私有数据库协调字段使用，不出现在公共运行对象或页面中。若历史秘密路径、快照或输入超出安全预算，服务会拒绝重试，而不是猜测或恢复原秘密。
