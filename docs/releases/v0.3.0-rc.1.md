# Agent Studio v0.3.0-rc.1

> 本候选版本面向源码使用者、工作流模板作者和节点包开发者试用，不是生产稳定版，也不提供 v1 兼容承诺。它在正式版前仍可能因阻塞缺陷调整；本说明不表示远端 Tag 或 GitHub Release 已存在。

## 版本与发布边界

Agent Studio Runtime 为 `v0.3.0-rc.1`，Go Node SDK 为 `0.3.0`，Node API 为 `agent-studio.dev/v1alpha1`。本 RC 是 Agent Studio 的候选 Release：只有标签工作流完成制品、四个原生目标和远端资产复核后，才会从 Draft 公开为 Pre-release；Tag 与公开 Release 均不可变。

Agent Studio Release 与官方节点索引 Release 是两条独立链路。本 RC 不会作为 stable 索引 Release 收录，也不会让任意节点包自动进入索引。索引收录只表示固定来源的元数据已审核，不是节点包代码安全认证。

## v0.3-A：工作流模板

可以从画布导出当前草稿为本地 JSON 模板，并先预览再导入为新的未发布工作流；模板不会覆盖现有数据。新模板使用 `agent-studio.dev/v1alpha2`，在 `spec.nodePackages` 中保存导出环境的节点包与节点类型，供导入预览显示兼容提示。该字段不是安装清单：缺包、版本不匹配或明文凭据会阻止导入，系统不会下载、安装、启用或执行任何节点代码。

## v0.3-B：节点包

节点包以 Module 根目录的 `agent-studio.node-package.json` 声明身份、SDK/Runtime 兼容范围和节点集合。`node package init`、`node inspect`、`node test` 与 `generate` 支持离线检查和确定性注册；第三方包必须由维护者审查源码后，明确版本手工安装并提交依赖与生成物。节点仍在 API 进程内运行，capability 只是展示和审计元数据，不是沙箱。

## v0.3-C：官方节点索引

CLI 提供只读的本地查询和显式刷新：

```bash
agent-studio node index status
agent-studio node index refresh
agent-studio node search
agent-studio node info github.com/example/node-package
```

API 与 Web 目录（`/node-packages`）只读取 embedded 快照或本地 cache；搜索、详情和打开页面不会联网。只有 `node index refresh` 会访问官方索引 Release 并写缓存，程序绝不后台刷新，也不会自动安装节点包。

默认缓存为 Go 用户缓存目录的 `agent-studio/node-index/index.json`。容器部署应将 API 与同版本 CLI 指向同一绝对路径，并共享 Docker volume：

```yaml
services:
  api:
    environment:
      AGENT_STUDIO_NODE_INDEX_CACHE_DIR: /var/lib/agent-studio/node-index
    volumes:
      - node-index:/var/lib/agent-studio/node-index
volumes:
  node-index:
```

若缓存损坏或刷新失败，保留上一个有效缓存或回退到 embedded 快照；请检查 `status` 的 warning 后重试显式刷新。

## 从 v0.2.0 升级与回滚

从 `v0.2.0` 升级前，先备份数据库和本地模板。旧的 v1alpha1 模板仍可导入，重新导出后会升级为 v1alpha2；节点包提示不会自动变更已有依赖。请逐个审查新模板及其声明的节点包，再运行 `doctor`、`node inspect` 和生成检查。

需要回滚时，停止 API，恢复升级前的数据库与模板备份，检出并重新部署 `v0.2.0` 的已验证构建。不要移动、覆盖或删除 RC Tag/Release，也不要以删除缓存替代数据库回滚；如 RC 出现阻塞问题，应发布递增 RC。

## 安装与制品验证

仅在远端 Tag 可用后，使用以下精确源码安装命令：

```bash
CGO_ENABLED=0 go install github.com/yyl1212/agent-studio/cmd/agent-studio@v0.3.0-rc.1
agent-studio version
```

仅在 Release 公开后下载四个支持目标（Linux/macOS 的 amd64、arm64）的附件。每个归档都应有对应 SPDX JSON SBOM，另有 `checksums.txt`。示例：

```bash
VERSION=v0.3.0-rc.1
OS=darwin
ARCH=arm64
ARCHIVE="agent-studio_${VERSION}_${OS}_${ARCH}.tar.gz"
BASE_URL="https://github.com/yyl1212/agent-studio/releases/download/${VERSION}"
curl -fLO "${BASE_URL}/${ARCHIVE}"
curl -fLO "${BASE_URL}/checksums.txt"
grep "  ${ARCHIVE}$" checksums.txt | shasum -a 256 -c -
tar -xzf "${ARCHIVE}"
./agent-studio version
```

Linux 可将最后的校验命令替换为 `grep "  ${ARCHIVE}$" checksums.txt | sha256sum -c -`。SHA-256 只确认下载内容与 Release 附件一致，不证明发布者身份；macOS 二进制未签名也未公证。

## 已知限制与安全报告

- 当前是单租户、本地部署；不包含登录、RBAC、团队协作或审计后台。
- 工作流只支持 DAG；不支持循环、人工审批、定时触发或分布式队列。
- 不提供 Windows 二进制、安装器、容器镜像、代码签名或 macOS 公证。
- 索引审核、模板兼容提示和节点 capability 都不替代源码、依赖、许可证与运行环境的安全审核。

请勿在公开 Issue 中披露漏洞、密钥或可利用细节；安全问题请按 [SECURITY.md](../../SECURITY.md) 的私密流程报告。
