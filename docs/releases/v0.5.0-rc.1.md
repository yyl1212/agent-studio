# Agent Studio v0.5.0-rc.1

> 此 RC 供源码使用者、工作流作者、节点包开发者和运维人员在隔离环境验证。它是非生产稳定版，不提供 v1 兼容承诺；出现阻塞缺陷时应使用后续 RC，而不是把它当作生产升级目标。

## 使用前的边界

本说明中的安装与附件步骤只在 `v0.5.0-rc.1` 标签工作流成功后适用。在此之前，请使用本地源码构建并以实际 Tag、校验和和附件状态决定下一步；不要假定远端标签或附件可用。

版本矩阵如下：

| 项目 | 值 |
| --- | --- |
| Runtime 源码开发构建 | `0.5.0-dev` |
| Go Node SDK | `0.5.0` |
| Node API | `agent-studio.dev/v1alpha1` |
| RC 目标 | `v0.5.0-rc.1` |

## 本 RC 包含的范围

- **v0.5-A 可观测性**：Worker 记录队列深度、最老排队时间和队列采样结果，供运维确认领取、租约和排队情况。
- **v0.5-B 画布体验**：画布与工作台继续提供节点配置、草稿保护、版本比较和运行入口。
- **v0.5-C 备份恢复**：备份格式为 `agent-studio.dev/backup/v1alpha2`，可导入受支持的 `v1alpha1` 归档；恢复后的活动运行仍按恢复规则处理。
- **v0.5-D 持久运行**：API 将运行写入 PostgreSQL 队列，独立 Worker 领取并执行；租约异常或无法确认副作用的运行进入人工恢复。

## 安装与制品核验

标签工作流成功后，可按精确版本安装 CLI：

```bash
CGO_ENABLED=0 go install github.com/yyl1212/agent-studio/cmd/agent-studio@v0.5.0-rc.1
agent-studio version
```

同一条件满足后，预编译附件可覆盖四个 archive：`darwin_amd64`、`darwin_arm64`、`linux_amd64` 和 `linux_arm64`。每个 archive 对应一个 SPDX SBOM，另有 `checksums.txt`；先校验 checksum，再解压并执行 `agent-studio version`：

```bash
VERSION=v0.5.0-rc.1
OS=darwin
ARCH=arm64
ARCHIVE="agent-studio_${VERSION}_${OS}_${ARCH}.tar.gz"
BASE_URL="https://github.com/yyl1212/agent-studio/releases/download/${VERSION}"

curl -fLO "${BASE_URL}/${ARCHIVE}"
curl -fLO "${BASE_URL}/${ARCHIVE}.spdx.json"
curl -fLO "${BASE_URL}/checksums.txt"
grep "  ${ARCHIVE}$" checksums.txt | shasum -a 256 -c -
tar -xzf "${ARCHIVE}"
./agent-studio version
```

Linux 将校验命令替换为 `grep "  ${ARCHIVE}$" checksums.txt | sha256sum -c -`。checksum 只能确认文件一致；本 RC 无签名/公证，macOS 也没有签名或公证可供验证。

若已从同一标签下载四个 archive、四个对应 SPDX JSON SBOM 和 `checksums.txt` 到 `./release-assets`，可在源码检出中验证完整 9 件集合：

```bash
sh scripts/check-release-artifacts.sh collection ./release-assets "$VERSION"
```

## 部署、容量与升级

在固定维护窗口内，把同版本 API 与 Worker 一起部署到同一数据库，并为二者配置相同密钥 `RUN_PAYLOAD_ENCRYPTION_KEY`。先停止旧 API、旧 Worker 和写库工具，再执行 migration 7；不要让新旧进程混跑。操作顺序、队列检查和故障处置见 [v0.5-D 升级与回滚](../upgrades/v0.5-d.md)。

轻量 RC 基线为 1 API、1 Worker（concurrency 4）、500 Mock runs，并将整次演练限制为 10 分钟。它只记录该环境的可重复验证结果，不是 SLA，也没有为吞吐量或排队等待设置生产承诺。可运行：

```bash
make test-rc-capacity-e2e
```

若使用错误密钥，停止 Worker，核对受控 Secret；运行会进入人工恢复而不会静默执行。回滚只允许在停止全部新进程后，将升级前备份恢复到经批准的空目标数据库，并使用与其匹配的旧制品。禁止 migration 7 逆迁移，也禁止旧/新 API 或 Worker 混跑。

## 已知限制

- 单租户、本地优先；不提供登录、RBAC、多租户管理或审计后台。
- 无容器制品、Windows 制品或安装器；CLI archive 只覆盖前述四个目标。
- 无本地 RAG、Embedding 或向量数据库闭环。
- 无自动业务重试；涉及外部副作用的不确定运行必须由人员确认恢复或终止。
- 无签名/公证；校验和不能证明发布者身份。
