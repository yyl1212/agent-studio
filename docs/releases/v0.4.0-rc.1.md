# Agent Studio v0.4.0-rc.1

> 本候选版本面向源码使用者、工作流作者和节点包开发者试用，不是生产稳定版，也不提供 v1 兼容承诺。正式版前仍可能因阻塞缺陷发布递增 RC；本说明不表示远端 Tag 或 GitHub Release 已经存在。

## 版本与发布边界

- Agent Studio Runtime：`v0.4.0-rc.1`
- Go Node SDK：`0.4.0`
- Node API：`agent-studio.dev/v1alpha1`

Go SDK v0.4 新增公开的 `ExecutionSafety` 类型和 `Definition.ExecutionSafety` 可选字段。Node API 仍为 v1alpha1：旧节点缺失该字段时可以加载，但有效安全等级会保守设为 `side_effect`。只有标签工作流完成四个原生目标、校验和、逐归档 SBOM、远端资产和 immutable 状态复核后，才视为通过候选发布门禁。

若该标签工作流全部成功，GitHub Release 应以 `draft=false`、`prerelease=true` 的 Pre-release 公开，且不能成为 Latest Release。在此之前，本文不声称这些远端状态已经存在。

## v0.4 功能总览

### 调试回放与安全局部重跑

运行事件和节点快照会持久化为有序时间线。调试页可以查看节点输入、输出、活动端口、耗时、脱敏路径和安全公开错误，并从指定节点创建来源可追溯的局部运行。服务端会重新计算活动子图和历史冻结边，正确处理 fork/join 边界；秘密入口需要重新填写，必要冻结边含秘密时会拒绝重跑。

局部重跑按照 `pure`、`read_only`、`side_effect` 展示最高有效安全等级。未知值和空值均按 `side_effect` 处理，副作用运行必须显式确认。`ExecutionSafety` 是交互与确认契约，不是沙箱、权限边界或节点行为的技术保证；取消也不能撤销已经发生的模型费用、Webhook 或其他外部副作用。

### Studio 聚焦工作台

画布旁采用单一上下文工作台统一节点库、节点配置、测试结果和运行入口。节点输入先保存为本地草稿，端口解析完成后需要显式“应用配置”；切换节点、测试、发布和导出都会保护未应用草稿。画布节点、工具栏、Schema 表单和调试容器统一视觉语义，并覆盖桌面、窄屏和移动宽度的响应式操作。

### 工作流、运行管理与恢复

工作流列表支持分页、搜索、归档、恢复和详情入口。全局运行管理支持筛选、详情、安全公开错误、协作取消与失败运行的完整重试；局部重跑仍从调试回放进入。活跃运行可以通过持久化事件恢复，NDJSON 断线后可从最后序号继续接收；跨请求取消和服务端终态收敛避免浏览器断线留下悬挂状态。API 进程重启时未完成运行会安全收敛为“已取消”，不会自动续跑。

### 聚焦式 Agent 页面

公开 Agent 页面根据开始节点参数生成单栏表单，并固定使用加载时的不可变发布版本。页面配置可以在 Studio 中编辑并随版本发布；运行 ID 写入 URL，支持刷新恢复、断线续接、取消、复制结果和再次运行。结果区域覆盖文本、JSON 与无障碍状态反馈，新发布不会改写已经加载的页面或历史运行绑定。

### 工作流版本治理

Studio 可以分页查看发布版本，在节点、开始参数、连线、Agent 页面配置和画布布局五组语义中比较任意两个稳定快照。将历史版本恢复为草稿时会创建新的草稿修订，不改写历史版本或线上 Agent；回滚前保存单级撤销检查点，后续任意草稿编辑会使撤销失效。

## 数据库升级与回滚

本版本在初始 migration 后增加：

- `000002_run_debug.sql`：调试事件、节点快照和局部运行来源。
- `000003_management.sql`：工作流归档与运行管理字段。
- `000004_run_recovery.sql`：运行心跳、恢复和终态收敛。
- `000005_agent_page.sql`：Agent 页面配置与发布快照。
- `000006_workflow_version_governance.sql`：版本治理、回滚和撤销检查点。

升级前必须备份 PostgreSQL 数据库、`.env`、本地模板和节点索引缓存，并验证数据库备份可以恢复。`.env` 可能包含模型、Webhook 等敏感配置，必须使用受限权限安全保存；节点索引缓存可以通过显式刷新重建，但应保留当前受测副本，以便复现原运行环境。迁移只向前执行；需要回滚时应停止 API，恢复与旧版本匹配的数据库备份、配置和本地资产，再部署旧版本二进制。不要把手工删除新表、移动 Tag 或覆盖 Release 当作回滚方案；RC 出现阻塞缺陷时发布递增 RC。

## 节点包兼容性

根目录官方节点包 manifest 的 Runtime 兼容范围为 `[v0.2.0, v0.5.0)`，覆盖 v0.4 Runtime。第三方节点包必须由维护者显式声明一个包含 v0.4 的 Runtime 半开区间，并通过 `node inspect`、`node test` 和生成检查；系统不会自动改写 manifest、下载、安装、启用或执行节点包。

节点代码仍与 API 运行在同一进程中。索引元数据、manifest、Capability 和 `ExecutionSafety` 都不能替代源码、依赖、许可证、密钥和运行环境的安全审核。

## 安装与制品验证

仅在远端 Tag 可用后，使用精确版本安装源码：

```bash
CGO_ENABLED=0 go install github.com/yyl1212/agent-studio/cmd/agent-studio@v0.4.0-rc.1
agent-studio version
```

仅在 Pre-release 公开后下载 Linux/macOS 的 amd64、arm64 附件。每个归档应有对应 SPDX JSON SBOM，另有 `checksums.txt`：

```bash
VERSION=v0.4.0-rc.1
OS=darwin
ARCH=arm64
ARCHIVE="agent-studio_${VERSION}_${OS}_${ARCH}.tar.gz"
BASE_URL="https://github.com/yyl1212/agent-studio/releases/download/${VERSION}"

curl -fLO "${BASE_URL}/${ARCHIVE}"
curl -fLO "${BASE_URL}/checksums.txt"
grep "  ${ARCHIVE}$" checksums.txt | shasum -a 256 -c -
tar -xzf "${ARCHIVE}"
./agent-studio version
```

Linux 可将校验命令替换为 `grep "  ${ARCHIVE}$" checksums.txt | sha256sum -c -`。SHA-256 只能确认附件内容一致，不能证明发布者身份；macOS 二进制未经过 Apple Developer ID 签名或公证。

## 已知限制

- 当前是单租户、本地优先部署，不包含登录、RBAC、多租户管理或审计后台。
- 运行仍在 API 进程内执行，不包含独立 Worker、分布式队列、服务重启后自动续跑或跨实例调度。
- 工作流只支持 DAG，不支持循环、人工审批或定时触发。
- 不提供 Windows 二进制、安装器、容器镜像、代码签名或 macOS 公证。
- 不包含文件上传、联网搜索、本地 RAG、Embedding 或向量数据库闭环。
- 本 RC 只证明发布门禁和制品验证结果，不承诺经过固定时间的生产观察。

安全问题请勿连同密钥或可利用细节提交到公开 Issue；请按 [SECURITY.md](../../SECURITY.md) 的私密流程报告。
