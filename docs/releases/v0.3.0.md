# Agent Studio v0.3.0

> 这是面向源码使用者、工作流模板作者和节点包开发者的正式开发者预览版，不是生产稳定版，也不提供 v1 兼容承诺。本说明不预先宣称远端 Tag 或 GitHub Release 已存在；安装和下载请以远端实际状态为准。

## 版本与发布边界

Agent Studio Runtime 为 `v0.3.0`，Go Node SDK 为 `0.3.0`，Node API 为 `agent-studio.dev/v1alpha1`。正式 Tag 与公开 GitHub Release 一经创建即不可变；创建 Tag 前的管理员检查会确认仓库已启用 Immutable Releases，标签工作流随后创建 Draft、上传并复核受测资产，转正后必须由 GitHub Release API 确认 `immutable=true`。

若正式标签工作流全部成功，GitHub Release 应以 `draft=false`、`prerelease=false` 公开并标记 Latest；在此之前，本文不表示该远端状态已存在。

GA 前必须由包含 v0.3-A/B/C/D 的候选版本完成四平台制品、SBOM、checksum、源码安装、当前平台原生归档和 immutable 技术门禁验证；这些验证不代表经过固定时间观察。

Agent Studio Release 与官方节点索引 Release 是独立发布物。`v0.3.0` 不会自动把节点包收录到索引；只有节点包经过独立、stable、immutable 的索引 Release 审核后，才会进入官方索引。收录只说明固定来源的元数据已审核，不是对节点包代码的安全认证。

## v0.3-A：工作流模板

画布可将当前草稿导出为本地 JSON 模板，并在不写入数据库的预览后导入为新的未发布工作流，不会覆盖现有数据。新模板使用 `agent-studio.dev/v1alpha2`，以 `spec.nodePackages` 记录导出环境的节点包和节点类型，供兼容性提示使用。这个提示不是安装清单：系统不会因导入而下载、安装、启用或执行节点代码。

## v0.3-B：节点包

节点包使用 Module 根目录的 `agent-studio.node-package.json` 声明身份、SDK/Runtime 兼容范围和节点集合。`node package init`、`node inspect`、`node test` 和 `generate` 提供离线检查与确定性注册。第三方包必须先人工审查源码，再以明确版本手工安装并提交依赖和生成物；节点与 API 同进程运行，capability 仅用于展示和审计，不构成沙箱。

## v0.3-C：官方节点索引

以下命令区分本地读取与显式刷新：

```bash
agent-studio node index status
agent-studio node index refresh
agent-studio node search
agent-studio node info github.com/example/node-package
```

API 和 Web 的 `/node-packages` 目录只读取 embedded 快照或本地 cache；浏览、搜索和详情不访问 GitHub。仅 `node index refresh` 会联网读取官方索引 Release 并写缓存，程序不后台刷新，索引也不自动安装节点包。

默认缓存位置在 Go 用户缓存目录的 `agent-studio/node-index/index.json`。在 Docker 中，让 API 与同版本 CLI 共用同一缓存路径和 volume：

```yaml
services:
  api:
    environment:
      AGENT_STUDIO_NODE_INDEX_CACHE_DIR: /var/lib/agent-studio/node-index
    volumes:
      - node-index:/var/lib/agent-studio/node-index
volumes:
  node-index:
```

缓存损坏或刷新失败时，系统保留上一个有效缓存或回退到 embedded 快照；使用 `agent-studio node index status` 查看 warning，再执行显式刷新恢复。

## v0.3-D：LLM v2 严格结构化输出

节点库同时提供 `LLM`（`llm@1`）与 `LLM · 结构化输出`（`llm@2`）。v2 可选择文本或 structured 模式；structured 模式通过通用低代码表单声明 1–32 个字段，支持字符串、数字、整数、布尔值和字符串数组。取消“必填”的字段使用 nullable 语义。节点输出完整 `json`、按配置顺序生成的逐字段动态端口和 `usage`；修改字段后必须修复画布上失效的旧连线。

默认 Mock Provider 无需密钥即可演示确定性结构化结果。OpenAI-compatible 服务必须原生支持 Chat Completions strict JSON Schema `response_format`；系统不会退回提示词约束、隐藏重试或发起第二次模型调用。结果还会经过 1 MiB 限制、`UseNumber` JSON 解码、尾随值检查和本地 Schema 二次校验。模型拒绝、认证失败、不支持 structured 或输出不合法时只返回固定公开错误，不包含 Provider 原始正文、模型输出、Schema、Prompt 或密钥。

本版本不包含工具调用、多模型降级、联网搜索、文件上传、本地 RAG、Embedding 或向量数据库。

## 从 v0.2.0 升级与回滚

升级前备份数据库和本地模板。v1alpha1 模板继续可导入，重新导出后会变为 v1alpha2；节点包声明仅用于预览提示，不会修改既有依赖。逐一审查模板与声明的包，再运行 `doctor`、`node inspect` 和生成检查。

需要回滚时，停止服务，恢复 `v0.2.0` 时的数据库与模板备份，并部署已验证的 `v0.2.0` 构建。不可移动、覆盖或删除已创建的正式 Tag/Release；后续修复应使用新的版本。删除索引缓存不能代替数据库或应用回滚。

## 安装与制品验证

仅在远端 Tag 可用后，使用精确命令安装：

```bash
CGO_ENABLED=0 go install github.com/yyl1212/agent-studio/cmd/agent-studio@v0.3.0
agent-studio version
```

仅在 Release 已公开后下载 Linux/macOS 的 amd64、arm64 归档、相应 SPDX JSON SBOM 和 `checksums.txt`。示例：

```bash
VERSION=v0.3.0
OS=darwin
ARCH=arm64
ARCHIVE="agent-studio_${VERSION}_${OS}_${ARCH}.tar.gz"
BASE_URL="https://github.com/yyl1212/agent-studio/releases/download/${VERSION}"
curl -fLO "${BASE_URL}/${ARCHIVE}"
curl -fLO "${BASE_URL}/checksums.txt"
grep "  ${ARCHIVE}$" checksums.txt | shasum -a 256 -c -
tar -xzf "${ARCHIVE}"
./agent-studio version
```

Linux 使用 `grep "  ${ARCHIVE}$" checksums.txt | sha256sum -c -`。SHA-256 只验证下载字节与 Release 附件一致，不能证明发布者身份；macOS 二进制未签名也未公证。

## 已知限制与安全报告

- 单租户、本地部署；没有登录、RBAC、团队协作或审计后台。
- 工作流仅支持 DAG；不支持循环、人工审批、定时触发或分布式队列。
- 不提供 Windows 二进制、安装器、容器镜像、代码签名或 macOS 公证。
- 不包含工具调用、多模型降级、联网搜索、文件上传或本地 RAG。
- 节点包审核、索引元数据、模板兼容提示与 capability 都不替代源码、依赖、许可证和运行环境的安全审核。

请通过 [SECURITY.md](../../SECURITY.md) 的私密渠道报告安全问题，勿在公开 Issue 中包含漏洞细节或密钥。
